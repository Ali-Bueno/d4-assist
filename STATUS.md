**Last updated:** 2026-09-30 — game update 3.2.2.73764: the app now finds its memory addresses itself (G, attribute names, pool tables, conversations), so small updates no longer break it. Earlier: blood petals no longer silenced on sight (false `+0x4D4` mark removed); the Lilith petal scene is a muted conversation; `D4MemScan screens`. Earlier: radar in story areas (the Darkened Way, Tristram, the hells, the Mercenary den) from the decoded compressed nav data (`m_cellBytes`); D2R's NPC tap, radar Exit from known doorways, blood petals as quest objectives, exploration kept across app restarts. Story-area radar, portal beacons, same-instance warps, radar wall memory: not live-tested. Repo: private GitHub `Ali-Bueno/d4-dungeon-assist`.

## Identity

- **Engine / framework:** Blizzard proprietary ("Fenris"), always-online. **No modding framework, no injection** — this is an *external companion app*; the game install and process stay untouched.
- **Screen-reader transport:** .NET 10 companion app → PRISM via the Prismatoid 0.3.0 NuGet package (backend NVDA live).
- **Build command:** `dotnet build`
- **Game install:** `D:\games\battlenet\Diablo IV` (build 3.2.2.73764 since 2026-09-30; memory addresses found at start, [client-memory](research/client-memory.md) §6)
- **Run / test:** `dotnet build D4DungeonAssist.sln`, `dotnet test D4DungeonAssist.sln` (628 tests). Run `src/D4Assist/bin/Debug/net10.0-windows/win-x64/D4Assist.exe --debug > log.txt`, then play; it idles in menus and loading screens, reads position + actors in the overworld and everything in dungeons (world from `FenrisDebug.txt`). Flags and config (`d4assist.json`): [src/D4Assist/README](src/D4Assist/README.md). The exe must be stopped before rebuilding (file lock).
- **Code map:** `src/D4Data` (offline CASC), `src/D4Memory` (read-only process access, scene route, player record), `src/D4Assist.Navigation` (rooms, openings, spoken announcements), `src/D4Assist.Radar` (D2R radar port), `src/D4Assist.Audio` (cue synth + WinMM mixer), `src/D4Assist` (app: `Game/GameSession`, `NavigationBridge`, `RadarBridge`); `tools/D4MemScan` (live RE diagnostics, e.g. `scene-route --diagnose --slots`), `tools/D4DungeonDump` (offline dumps). Each has a README.
- **Brief:** [`diablo4-dungeon-assist-research-for-claude.md`](diablo4-dungeon-assist-research-for-claude.md)

## User and decisions

- **Player:** blind; plays with a **controller** and NVDA through D4's third-party screen-reader option. Talk to them in Spanish; speech output is Spanish. Design around screen-relative stick directions and few extra buttons. Any TTS capture must keep NVDA speaking the game's text.
- **Risk (2026-09-26):** the user accepted the ban risk of **read-only** memory reading on their main account (no second account). Don't re-litigate it. Don't suggest asking Blizzard: promised for 3 years, nothing delivered, Diablo 5 announced. Never write to or inject into the game, never implement anti-cheat evasion or stealth, and keep live RE sessions short. **2026-09-29: the user approved reading memory outside dungeons too** (overworld, story areas) for beacons to map points and quest objectives ("no estamos haciendo nada que haga cheating").
- **Guidance to story points (2026-09-29):** the user asked for beacons to map points and to campaign story points (example: shelters from the act 3 desert storms). Built as data-driven campaign routes; map points and "follow the active quest" come later (2026-09-30: the tracked quest is the player ACD's `ManuallyTrackedQuestSNO`; its actors aren't linked yet, but quest gizmos on the minimap already get the quest loop).
- **Minimap computer vision:** rejected by the user as imprecise and needing per-resolution/per-PC setup. Don't propose it without new evidence.
- **Navigation audio = the user's D2R radar** (`D:\code\c++\diablo 2 access project\d2r-access`, read-only, never modify): same cues, 4-ray Cardinal frame, same anti-spam, cues one after another. Copy the D2R design first and deviate only when D4 forces it or the user asks. The one requested deviation: the open-floor breath must sound clearly different up vs down (the user fixes D2R themselves).
- **Radar-only worlds:** built 2026-09-28 for the Mercenary den (video). 2026-09-30: the user asked for the radar in the Darkened Way; every story area (non-DRLG world but the open world) now gets it automatically. **Open world: no radar** (user 2026-09-30: Blizzard's own navigation assist works well there; enable it only if that stops working).
- **Features (2026-09-28):** first = automatic spoken announcements (junctions, dead ends, big rooms) in stick directions, then the radar. Language: C# (.NET 10).
- **Live sessions (2026-09-29):** after each new feature, stop the running app, rebuild and relaunch it with `--debug` without asking.
- **Repository:** private GitHub `Ali-Bueno/d4-dungeon-assist`. Never make it public without asking (it reads game memory).
